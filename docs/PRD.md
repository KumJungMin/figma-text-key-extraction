# PRD — Figma Text Key Extraction

- 버전: v0.1 (2026-11-22)
- 상태: Draft
- 대상: Figma Plugin (read-only)
- 관련: [기능 요구사항](REQUIREMENTS.md) · [키 규칙](KEY_RESOLUTION.md)

## 1. 문제 정의

다국어 문구의 최종 디자인 마스터가 Figma일 때, TextNode의 변경 사항을 개발용 번역 리소스로 반영하려면 수동 복사·엑셀 대조가 필요하다. 이 과정에서 누락, 중복, 서로 다른 공통 문구, 키/문구 불일치가 발생한다. Figma에 명명된 i18n 키와 실제 문자열을 정형 데이터로 추출해 개발 전달 비용과 실수를 줄인다.

## 2. 목표와 사용자

- 주요 사용자: Figma 문구를 관리하는 디자이너, 번역·키를 관리하는 기획/운영, JSON 리소스를 받는 프론트엔드 개발자.
- 목표 1: 화면별·공통 문구를 지정된 키 기준으로 추출한다.
- 목표 2: 중복 및 불일치를 검증하여 잘못된 JSON 반영을 막는다.
- 목표 3: TextNode를 수정하지 않고 미리보기·JSON 다운로드까지 제공한다.
- 목표 4: 기존 `sheets-i18n-figma-sync`의 `*key` 방식과 가능한 범위에서 규칙을 맞춘다.

## 3. 확정된 제품 결정

| ID | 결정 | 상태 |
| --- | --- | --- |
| PD-01 | 화면별 네임스페이스는 Figma Page 이름이 아닌 화면 Frame 이름 사용 | 확정 |
| PD-02 | `*common.xxx` 절대 키와 `common` Group/Frame 상대 키 모두 지원 | 확정 |
| PD-03 | 화면/공통 리소스를 합쳐 언어당 하나의 Nested JSON 출력 | 확정 |

## 4. 사용자 흐름 (제안)

1. 플러그인을 열고 추출 범위(현재 Page / 선택 영역 / 전체 파일)를 고른다.
2. 현재 화면 텍스트의 언어를 명시적으로 선택한다(예: `ko`). **번역 기능이 아님**을 설명한다.
3. `Scan` 실행: TextNode 탐색 → 키 해석 → 문자열 수집 → 중복/충돌 검증.
4. 건수 및 진단 목록(키·문구·Figma 위치)을 미리보고 필요하면 레이어 이름/문구를 고친다.
5. 오류가 없을 때 `Export JSON`으로 `ko.json`을 다운로드한다.
6. 입력된 Figma 텍스트와 레이어 구조는 변경하지 않는다.

## 5. 핵심 사용 사례

- US-01: 디자이너는 `ez.join.idCardCamera` Frame의 `*title`을 `"신분증 촬영"`으로 추출한다.
- US-02: 여러 화면에서 `*common.confirm`을 사용하여 `common.confirm` 한 건으로 병합한다.
- US-03: `common` 그룹의 `*cancel`을 화면과 무관하게 `common.cancel`로 추출한다.
- US-04: `common.confirm`에 `"확인"`과 `"완료"`가 공존하면 어디에서 충돌했는지 확인한다.
- US-05: 특정 Frame만 선택해 추출하고, 이후 전체 파일 추출 결과와 비교할 수 있다(차이 비교 자동화는 MVP 제외).

## 6. MVP 범위

**포함:** TextNode read-only 조회, 화면/공통 키 해석, `*key` 조상 상속(하위 텍스트 1개), 세 범위 탐색(제안), 원문 값 보존, 중복/충돌 검증, 결과 요약과 오류 위치, 통합 Nested JSON 다운로드.

**제외:** AI 번역, 언어별 자동 검출, Google Sheets 저장/동기화, 역방향 Figma 쓰기, 기존 JSON Diff, pluginData 키 저장.

## 7. UX와 사용자 피드백

- 초기/스캔 중/완료/오류/충돌 상태를 구분한다.
- 요약 수치: 탐색 TextNode, 키 발견, 출력 키 수, 동일 중복 수, 무시/경고 수, 차단 오류 수.
- 이슈마다 코드·사유·관련 키·Page/Frame/Node 이름과 ID를 표시한다.
- 데이터가 없으면 다운로드 버튼을 비활성화한다.
- 오류가 있는 상태에서 묵시적으로 일부 키만 출력하지 않는다(기본 정책 제안).
- 선택 영역 모드에 선택 항목이 없으면 구체적인 안내를 표시한다.

## 8. 성공/완료 기준

- [ ] 확정된 세 가지 제품 결정이 끝까지 지켜진다.
- [ ] 정상 키는 일관된 JSON으로 변환되며 원본 문구의 줄바꿈/플레이스홀더가 보존된다.
- [ ] 같은 키/같은 값은 병합되며 같은 키/다른 값과 JSON 경로 충돌은 검출된다.
- [ ] 검사 후 다운로드할 때 Figma의 어떠한 노드도 수정되지 않는다.
- [ ] [TEST_PLAN](TEST_PLAN.md)의 필수 P0 시나리오가 모두 통과한다.

## 9. 아직 확정되지 않은 기본 정책

기본값 제안은 문서 간 일관성을 위해 잠정 채택한다. 제품 결정으로 확정하려면 리뷰에서 승인한다.

- 숨김 TextNode와 Component/Instance 포함 여부
- `FRAME` 네임스페이스 최소 두 세그먼트(`a.b`) 규칙
- 전체 파일 스캔 기본 제공 및 성능 목표
- 공백만 있는 값 제외 및 충돌이 하나라도 있으면 Export 차단
- 언어 코드 입력/선택 방식
